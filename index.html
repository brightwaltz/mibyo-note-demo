PRODUCT DEMO / 01

30秒の記録に、必ず「返事」が返る

記録アプリが続かない理由は単純で、書いても何も返ってこないからです。未病ノートは記録の直後に必ず3種類の返事を返します。左の端末は実際に動きます。「今日の体調を記録する」から一巡してみてください。

この画面で見ていただきたい3点

① 12項目が実質3〜5タップで終わること　② 記録直後に「あなたと同じ人がいる」と返ること　③ 「去年の今頃」が話題として返ること。

返事①　共感カード

鍼灸院で「この時期、私みたいな人いますか」と聞いて「いますよ」と返ってくる、あの安心を画面上で再現します。年代×性別×地域×節気×体調のコホートで人数を返します。左の端末の「DEMO CONTROL」で登録者数を切り替えると、データが貯まる前の見え方をその場で確認できます。

  • 階層バックオフで「0人」を構造的に出さない。年代6×性別2×地域8×体質4＝384セルに切ると、1セルが n≥30 に届くには約38,400名が必要です。母数が足りなければ条件を1つずつ外し（地域→体質→性別）、最初に n≥30 を満たした段で返します。文言も「関東の40代女性」から「40代の方」へ正直に落とすだけで、0人にはなりません
  • 母数で「返すもの」を変える。n≥30 は人数＋「実測」、10≤n<30 は割合のみ＋「推定」、n<10 は人数も割合も出さず節気の傾向カードに差し替えます。どの段でも「返事が返ってこない」ことは起きません
  • n<10 で人数を出さないのは規約通り。労働安全衛生法の集団分析が10人以上単位であることと同じ基準なので、「隠している」ではなく「規約通り」と説明できます
  • 割合はベイズ縮約で安定させる。p =（x + 20·p₀）/（n + 20）で上位階層の割合に寄せるため、3人中0人でも 0% にはなりません
  • コホートの単位は「いま」ではなく「この節気」。その節気（約15日）に記録があった人で切るため、追加コストなく母数が実質15倍になります
  • 合成データで人数を水増ししない。表示は推定／実測をラベルで分離し、内部は実測のみ蓄積します。ここを曖昧にすると研究利用時の倫理審査で止まります

返事②　去年の今頃（回想）

他人との共感だけでは、記録をやめた人は戻ってきません。もう一つの継続動機が自分の周期性への気づきです。「案外、去年も同じ時期に同じことを書いている」という発見は、天気予報のような話題性を持ちます。

  • 比較の単位を「年」ではなく「節気」に置く。二十四節気は年24回訪れるため、登録から3か月で6回の比較点が生まれます。「去年」を待たずに回想機能が動き出すのがこの設計の要点です
  • 1年続けた人にしか「去年の自分」は出せない。継続そのものが乗り換えコストになり、解約防止として働きます

返事③　養生のひとこと

節気に応じた一般的な生活の工夫のみを返します。診断・治療の示唆、症状名の断定、受診の要否判断は行いません（医師法17条・薬機法への配慮）。文言は固定文言テーブルからの出力で、生成AIによる自由生成は本番でも使いません。

入力設計

  • 12項目＝12タップですが、前日の回答を初期値としてプリセットするため、2日目以降は変わった項目だけを触ります。左の端末でタップ数が実測表示されます
  • 4軸（気・血・水）に3項目ずつ、心に3項目。同じことを二度聞かないため、「睡眠の質」と「寝つき」のような重複は1項目に統合しています
  • 法定ストレスチェックの調査票項目そのものは使わず、日常語の4段階に留めます

濃いほど不調。梅雨と夏の終わりに山が立つのが、この会社の型です。

この山の位置が分かると、産業医面談・繁忙期の人員配置・健康施策の実施時期を前もって決められます。年1回のストレスチェックでは得られない情報です。

何に使えるか

  • 健康経営優良法人の申請材料。「実施した施策」だけでなく「施策の前後で集団の指標がどう動いたか」を出せます
  • 休職の予兆。個人ではなく部署単位で、心の軸が3節気連続で下降した組織に対して面談枠を先に用意します
  • 派遣スタッフの定着。就業開始90日以内の離職が多い層に、就業先ごとの傾向を持てます
  • ストレスチェックの補完。置き換えではありません。法定の実施義務は従来どおり、実施者要件（医師・保健師等）を満たす体制で行います

この事業で最初に壊れるとしたら、ここです

「会社に体調を監視される」と受け取られた瞬間に、参加率は上がりません。①完全任意参加 ②個人の回答は人事に渡らないことを実装と規程の両方で担保 ③従業員代表への事前説明。この3点を導入条件として最初から固定します。

OPERATIONS / 03

この画面は、いくらで動いているか

いまご覧いただいているデモの運用費は月額0円です。サーバーもデータベースも使っていません。以下が、デモ・公開テスト・スケール後の3段階の構成です。

DEMO
いまこの画面¥0
HTML1枚 + GitHub Pages。サーバー処理なし、データベースなし、外部への送信なし。記録した内容はご覧の端末のブラウザ内（localStorage）にのみ保存され、こちらからは見えません。表示中の人数・他者データはすべて端末内で生成したサンプルです。URLを渡すだけで誰でも開けます。
PHASE 1
公開テスト¥0
Cloudflare Pages（無料枠・商用可）+ Supabase（無料枠）。DB 500MB・月間アクティブユーザー5万まで無料。1ユーザーあたり年間の記録は約15KBのため、500MBは概算で3万人年ぶんに相当します。認証・行単位セキュリティ（RLS）・定期実行まで無料枠に含まれます。この段階で実ユーザーの数値が取れます。

Vercelの無料枠は商用利用が規約で禁止されているため採用しません。Renderの無料枠はアクセスが無いとサーバーが停止し、朝の通知が飛ばないため不適です。
PHASE 2
法人導入後実費
Supabase Pro（$25/月〜）+ 通知基盤。有料化の判断点は「無料枠を超えたとき」ではなく「法人契約が1件決まったとき」です。監査ログ・日次バックアップ・SLAは法人が求める要件であり、そのコストは法人側の売上で回収します。ユーザーが増えても、法人契約が無いうちは無料枠の内側に留めます。
DATA
研究利用
仮名加工したうえで、取得時に個別同意を得たデータのみを解析対象にします。要配慮個人情報にあたるため、オプトアウトによる第三者提供はできません。研究として公表する場合は倫理審査委員会の承認を前提とします。

法令上、越えない線

論点設計上の線引き
薬機法／プログラム医療機器診断・治療・予防を目的とした判定を行わない。記録の可視化と一般的な生活情報の提示に留めるため、医療機器プログラムに該当しない設計とする
医師法17条症状名の断定、受診要否の判断、個別の治療助言を出力しない。「気になることが続く場合は医療機関へ」という一般的な案内のみ
個人情報保護法体調データは要配慮個人情報。取得時の明示的同意、利用目的の限定、オプトアウト提供の禁止を実装で担保する
労働安全衛生法法定ストレスチェックの代替とはしない。集団分析は10人以上の単位のみ。実施者要件を満たす体制で別途実施する
研究倫理人を対象とする生命科学・医学系研究に関する倫理指針に従い、研究利用は倫理審査委員会の承認後に限る

このデモに入っていないもの（正直な現状）

  • アカウント登録・ログイン。デモは端末内で完結するため実装していません
  • 実際の他者データ。共感カードの人数は端末内で生成した架空の数値です。実データに置き換わるのは公開テスト以降です
  • プッシュ通知。「去年の今頃」の通知文面は画面内に表示するのみで、実際の配信は行っていません
  • 気圧・気温の自動取得。本番では外部APIから取得し交絡因子として保存しますが、デモでは通信を一切行わない方針のため省いています
